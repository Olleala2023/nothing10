# Архитектура

Что где лежит, что чему разрешено зависеть, как проект собирается и деплоится.

**Последний пересмотр:** 2026-07-25 · **Следующий:** 2027-01-25 (или при смене стека)

---

## Что это за проект

Статический сайт с встроенным PWA-приложением. Нет бэкенда, нет базы данных, нет
аутентификации. Всё состояние — в `localStorage` браузера пользователя.

Стек: Vite 7 + vanilla JavaScript (ES-модули) + CSS с кастомными свойствами. Хостинг —
Cloudflare Pages, автодеплой из ветки `main`.

Из этого следуют два практических вывода, которые определяют почти все решения ниже:

1. **Всё, что попало в `dist/`, публично.** Нет серверного слоя, который мог бы что-то
   скрыть. Лишний файл в сборке = лишний публичный URL.
2. **Нет сервера — значит нет и способа исправить данные пользователя.** Ошибка в формате
   `localStorage` остаётся у пользователя навсегда, миграцию накатить некому.

## Слои

Четыре слоя. Правила зависимостей между ними — главное, что этот документ защищает.

```
┌─────────────────────────────────────────────────────────────┐
│  Общий слой        public/styles/common.css                 │
│                    public/scripts/theme-toggle.js           │
│                    ↑ используется всеми, не зависит ни от кого│
└─────────────────────────────────────────────────────────────┘
      ↑                      ↑                       ↑
┌───────────┐   ┌────────────────────┐   ┌────────────────────┐
│  Лендинг  │   │  Приложение (PWA)  │   │ Статические страницы│
│ index.html│   │  src/app/          │   │ public/{tools,      │
│           │   │  + public/app/sw.js │   │  research,legal,…}  │
│ собирается│   │  собирается Vite    │   │ копируется как есть │
│   Vite    │   │  Service Worker     │   │ inline или .js рядом│
└───────────┘   └────────────────────┘   └────────────────────┘
```

### Правила зависимостей

- НУЖНО: общий слой не зависит ни от чего. `common.css` и `theme-toggle.js` подключаются
  на всех 21 странице и не могут ссылаться на код приложения или инструментов.
- НУЖНО: статические страницы не импортируют из `src/`. Они копируются в сборку без
  обработки, поэтому любой импорт из `src/` в них не разрешится.
- НУЖНО: приложение не зависит от кода инструментов, инструменты — от кода приложения. Общее
  выносится в общий слой.
- НЕ НУЖНО: обращаться к DOM-элементам чужого слоя. Каждый слой владеет своей разметкой.

### Источник правды

НУЖНО: приложение редактируется **только** в `src/app/`.

Каталог `app/` в корне — закоммиченный вручную устаревший артефакт сборки. Имена файлов
совпадают с `src/app/`, содержимое уже разошлось: нет кнопок шеринга, canonical, Open
Graph-тегов, описаний режимов при наведении. В сборке он не участвует, то есть правка в нём
не даёт ни ошибки, ни эффекта — код просто не доезжает до пользователя.

Подлежит удалению (`docs/DECISIONS.md`, запись 0001).

### Мёртвый код

Знать про него нужно, чтобы не принять за рабочий:

| Путь | Что это | Статус |
|---|---|---|
| `app/` | Устаревшая копия приложения | Удалить |
| `src/main.ts`, `src/counter.ts`, `src/typescript.svg` | Нетронутый стартовый шаблон Vite со счётчиком кликов | Удалить |
| `public/vite.svg` | Логотип Vite. **Попадает в прод**, уже закрыт в `robots.txt` | Удалить |
| `public/.htaccess` | Конфиг Apache, Cloudflare Pages его не читает. Попадает в прод и публично читается | Заменить на `_headers` |
| `sw.js` → обработчик `push` | Push-уведомления: код есть, подписки нет | Оставить как задел |
| `src/app/app.js:770-775` | Второй слушатель `visibilitychange`, целиком из комментариев | Удалить |

**Про TypeScript.** `tsconfig.json` в `include` содержит только `["src"]`, то есть покрывает
исключительно мёртвый шаблон. Реальный код приложения — `src/app/app.js`, обычный JavaScript.
Типизации в проекте фактически нет, несмотря на `strict: true` в конфиге и `typescript`
в зависимостях. Не считайте проект типизированным.

## Паттерны модулей

Сейчас в проекте три разных подхода к организации модуля:

| Паттерн | Где | Пример |
|---|---|---|
| Класс | `src/app/app.js` | `class NothingTimer` |
| IIFE с `'use strict'` | `public/scripts/theme-toggle.js` | `(function() { … })()` |
| Переменные на уровне модуля | `public/tools/*.js` (6 файлов) | `let data = null; let currentPair = null;` |

НУЖНО для нового кода: ES-модуль с экспортируемыми функциями. Класс — МОЖНО, если у сущности
есть состояние и жизненный цикл (как у таймера). Глобальные переменные на уровне модуля —
НЕ НУЖНО: они превращают порядок вызовов в неявный контракт.

Эталон качества в проекте — `public/scripts/theme-toggle.js`: обёртки `try/catch` вокруг
`localStorage`, JSDoc, `'use strict'`, явный публичный интерфейс. Берите его за образец
(но не копируйте создание SVG через `createElement` — там ошибка, см. `CODE_STYLE.md`).

### Дублирование, подлежащее устранению

Vite в стеке есть, но шаблонизация не используется — всё копируется руками:

| Что дублируется | Копий |
|---|---|
| Футер (7 ссылок) | 20 файлов |
| Head-boilerplate (~24 meta-тега) | 20 файлов |
| Реализация таймера | 4 |
| Логика чеклиста (`initChecklist` / `saveState` / `updateProgress`) | 5 файлов, отличаются только данными и ключом |

НУЖНО: не добавлять шестую копию чеклиста и двадцать первую копию футера. Новый инструмент
такого типа — повод вынести общий модуль, а не скопировать существующий файл.

## Состояние: localStorage

Единственное хранилище в проекте. Отсюда два жёстких правила.

### Реестр ключей

НУЖНО: любой новый ключ вносится в таблицу ниже **и** в `public/legal/privacy.html`.

| Ключ | Кто пишет | Что хранит |
|---|---|---|
| `completedSessions` | `src/app/app.js` | Счётчик завершённых сессий |
| `totalMinutesWeek` | `src/app/app.js` | Минуты (⚠️ подписано «за неделю», фактически за всё время) |
| `streakDays` | `src/app/app.js` | Длина серии дней |
| `lastSessionDate` | `src/app/app.js` | Дата последней сессии (⚠️ в UTC, а не локальная) |
| `phraseBucket` | `src/app/app.js` | Индекс мотивационной фразы |
| `reflections` | `src/app/app.js` | JSON-массив заметок пользователя, до 50 |
| `duration` | `src/app/app.js` | Выбранная длительность (⚠️ читается, но не пишется) |
| `displayMode` | `src/app/app.js` | Режим отображения (⚠️ читается, но не пишется) |
| `fullscreenUsed` | `src/app/app.js` | Флаг: кнопка fullscreen уже использовалась |
| `nothing10-theme` | `public/scripts/theme-toggle.js` | `dark` / `light` |
| `endPrompt` | `public/tools/end-prompt.js` | История, избранное, пользовательские записи |
| `checklist-10m-reset-checklist` | `public/tools/10m-reset-checklist.js` | Состояние галочек |
| `checklist-distraction-audit` | `public/tools/distraction-audit.js` | Состояние галочек |
| `checklist-focus-switch` | `public/tools/focus-switch.js` | Состояние галочек |
| `checklist-post-pause-checklist` | `public/tools/post-pause-checklist.js` | Состояние галочек |
| `checklist-sleep-winddown` | `public/tools/sleep-winddown.js` | Состояние галочек |

**Расхождение с юридическим текстом.** Privacy Policy (§2 и §4) перечисляет только ключи
приложения: статистику, настройки, «A/B Test Bucket», флаги и рефлексии. Тема оформления,
состояние шести инструментов и пользовательские записи в `endPrompt` **не упомянуты** —
а это семь ключей, включая пользовательский ввод. Для продукта, который продаёт себя через
приватность, неполный перечень локальных данных — заметный пробел. Требует правки
`privacy.html`.

Отдельно: `phraseBucket` описан в Privacy Policy как «A/B Test Bucket», но никакого
A/B-теста нет — значение никуда не отправляется и нигде не измеряется.

### Правила работы с хранилищем

- НУЖНО: каждое обращение обёрнуто в `try/catch`. В Safari Private Mode и при переполнении
  квоты `localStorage` выбрасывает исключение. Сейчас в `src/app/app.js` защиты нет ни в
  одном из ~18 обращений, в `theme-toggle.js` — есть.
- НУЖНО: при чтении JSON — валидировать результат, а не доверять форме. Данные могли быть
  записаны прошлой версией кода, и откатить их некому.
- НЕ НУЖНО: менять формат существующего ключа без миграции. Сервера, который починит данные,
  не существует. Меняете формат — новый ключ и код, умеющий читать оба.
- СТОИТ: свести доступ к хранилищу в один модуль общего слоя. Сейчас каждый файл работает
  с `localStorage` по-своему, поэтому и правила соблюдаются по-разному.

## Сборка

```bash
npm run build   # vite build && node scripts/move-app.js
```

Что происходит:

1. Vite собирает две входные точки (`vite.config.js`): `index.html` → `dist/index.html`
   и `src/app/index.html` → `dist/src/app/index.html`. JS и CSS приложения получают хеш
   в имени файла.
2. `public/` копируется в `dist/` как есть — без хеширования и минификации.
3. `scripts/move-app.js` переносит `dist/src/app/index.html` в `dist/app/index.html`.

Существенные особенности, о которых нужно знать:

- **`move-app.js` не переносит, а копирует.** Использует `readFileSync`/`writeFileSync`
  без удаления источника, поэтому `dist/src/app/index.html` остаётся в сборке и приложение
  доступно по лишнему публичному адресу `/src/app/`. Блок замены путей внутри скрипта
  заменяет строку на саму себя — операция без эффекта.
- **`public/styles/common.css` не проходит через Vite.** Подключается прямой ссылкой
  (`index.html:90`), поэтому не минифицируется и не получает хеш: cache-busting для самого
  большого CSS-файла на сайте отсутствует. То же касается `public/scripts/theme-toggle.js`
  и шести скриптов в `public/tools/`.

НУЖНО: после изменения сборки проверить состав `dist/` на предмет лишних файлов. Всё, что
попало в `dist/`, становится публичным URL.

## Деплой

Cloudflare Pages, автоматически из `main`. Настройки и первичная конфигурация —
в `DEPLOYMENT_GUIDE.md`.

```
Build command: npm run build
Output directory: dist
Production branch: main
```

Что важно помнить про поведение платформы:

- **Cloudflare Pages сам делает 308-редирект с `.html` на URL без расширения.** Отключить
  через `_redirects` нельзя. Поэтому канонические адреса — без `.html`, и все внутренние
  ссылки НУЖНО писать сразу без расширения (`/legal/privacy`, не `/legal/privacy.html`).
- **`_redirects` содержит правила для `/app`** — три строки со статусом 200 вместо редиректа,
  чтобы не возникало цепочки перенаправлений при индексации.
- **`.htaccess` не работает.** Это формат Apache. Защитные заголовки, описанные в нём
  (`X-Frame-Options`, `X-Content-Type-Options`), в production не применяются. Нужен
  `public/_headers` — см. аудит, п. 1.5.

## Service Worker

`public/app/sw.js`, зарегистрирован из `src/app/app.js:36` как `/app/sw.js`.

**Scope — `/app/`.** Это определяет всё остальное: SW контролирует только страницы внутри
`/app/`. Ветки его `fetch`-обработчика для `/legal/`, `/focus-lock/` и `/icons/` не исполняются
никогда — статические страницы вне scope.

Правила:

- НУЖНО: `CACHE_NAME` меняется при **каждом** изменении содержимого сборки. Сейчас имя
  зашито константой (`'nothing10-v2'`) и правится вручную. Если `sw.js` не изменился
  байтово, браузер не считает Service Worker обновившимся и продолжает отдавать
  закешированный `index.html` — пользователь остаётся на старой версии приложения навсегда.
- НУЖНО: для навигационных запросов — network-first или stale-while-revalidate. Cache-first
  допустим только для файлов с хешем в имени. Сейчас `/app/index.html` кешируется
  cache-first — это и есть механизм, по которому обновления не доезжают.
- НУЖНО: precache должен содержать всё, без чего приложение не запустится, включая
  собранные JS и CSS. Сейчас в нём только HTML, манифест и иконки, поэтому заявленная
  офлайн-работа на первом визите не работает.
- СТОИТ: генерировать `CACHE_NAME` из версии сборки, чтобы убрать ручной шаг.

Изменение `sw.js` — **всегда категория L** (см. `CONTRIBUTING.md`). Ошибка здесь не
проявляется у автора: у него кеш пустой. Проявляется у всех остальных, и починить её
удалённо нельзя.

## Границы, которые нельзя переходить

Сводка запретов с причинами. Каждый — следствие того, что бэкенда нет.

| Запрет | Почему |
|---|---|
| Не коммитить собранные артефакты | Вторая копия с теми же именами = правка не того файла (уже произошло с `app/`) |
| Не добавлять сторонние скрипты без записи в `DECISIONS.md` | Приватность — позиционирование продукта; сейчас по этому вопросу открытое решение 0003 |
| Не хранить в `localStorage` ничего чувствительного | Данные не шифрованы и доступны любому скрипту на домене |
| Не менять формат ключей без миграции | Исправить данные пользователя нечем |
| Не полагаться на `setInterval` для отсчёта времени | Браузер тормозит фоновые таймеры; накапливается дрейф |
| Не блокировать рендеринг скриптами в `<head>` | Даёт вспышку не той темы на всех 20 страницах |
| Не превышать одну входную точку на слой | Иначе `move-app.js` и `_redirects` придётся переписывать под каждую |
