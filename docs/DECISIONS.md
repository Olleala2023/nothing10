# Журнал решений

Здесь фиксируются решения, которые влияют на код, но не выводятся из него: почему выбран
такой подход, какие были альтернативы, что стало бы поводом передумать.

**Зачем это нужно.** Правило без причины со временем превращается в карго-культ: никто не
помнит, зачем оно, поэтому его либо боятся тронуть, либо нарушают не задумываясь. Именно так
и разъезжаются документы. Причина решения живёт здесь, само правило — в `CODE_STYLE.md`,
`ARCHITECTURE.md` или `TESTING.md`.

**Формат.** Один файл вместо каталога отдельных ADR — сознательно, по масштабу проекта.
Каталог из двадцати файлов по одному решению для сайта из 21 страницы никто не будет
поддерживать, а незаполняемый журнал хуже отсутствующего.

**Правила ведения:**

- Записи добавляются в конец, **старые не редактируются**. Передумали — новая запись со
  ссылкой на прежнюю, у прежней статус меняется на `Заменено (см. NN)`.
- Номера последовательные, не переиспользуются.
- Статусы: `Принято` · `Открыто` (нужно решение владельца) · `Заменено` · `Отклонено`.
- Запись обязательна, если изменение затрагивает архитектуру, стек, юридические тексты,
  приватность или отменяет действующее правило. Для обычных задач не нужна.

## 0001. Единственный источник правды для приложения — `src/app/`

**Дата:** 2026-07-25 · **Статус:** Принято

**Контекст.** В репозитории лежат две почти одинаковые копии приложения: `src/app/` и `app/`.
Вторая — устаревший артефакт сборки, закоммиченный вручную. Расхождение уже накопилось:
в `app/` нет кнопок шеринга, canonical, Open Graph-тегов и описаний режимов при наведении.

**Решение.** Источник правды — `src/app/`. Каталог `app/` в корне удаляется. В сборку попадает
только то, что собрал Vite.

**Состояние выполнения:** правило действует с этой даты — редактировать `app/` нельзя уже
сейчас. Само удаление каталога — отдельная задача (правка кода, не документации), на момент
записи не выполнена.

**Причина.** Две копии с одинаковыми именами файлов — это гарантированная правка не того
файла. Ошибка при этом не проявляется ни в сборке, ни в тестах: код просто не доезжает.

**Что стало бы поводом передумать.** Ничего. Собранные артефакты не коммитятся, точка.

## 0002. Политика тестирования: тест-первым для крупных изменений, освобождение для мелких

**Дата:** 2026-07-25 · **Статус:** Принято

**Контекст.** Тестов в проекте нет ни одного. История коммитов — цепочка ручных заплаток
(`fix`, `fix`, `Fix audit issues`), а аудит от 2026-07-25 нашёл две ошибки в подсчёте
статистики, которые поймал бы простейший unit-тест.

**Решение.** Порог по размеру изменения: крупные (L) — тест до кода, средние (M) — тест
вместе с кодом, мелкие (S) — без тестов. Каждое исправление бага сопровождается тестом,
падающим до фикса. Подробности и границы категорий — в `TESTING.md`.

**Причина.** Требовать 100% покрытия в проекте без тестов — верный способ не начать никогда.
Освобождение для мелких правок сохраняет скорость там, где риск действительно низкий, а
жёсткое требование на крупных изменениях закрывает то, где ломается по-настоящему.

**Альтернативы.** Полный TDD на всё — отвергнут как нереалистичный для соло-разработки.
Тесты «когда-нибудь потом» — уже пробовали, результат в аудите.

**Что стало бы поводом передумать.** Если ядро (`docs/TESTING.md`, раздел «Обязательное
покрытие») закрыто тестами и держится полгода, порог для M можно поднять до test-first.

## 0003. Позиция по трекингу и приватности

**Дата:** 2026-07-25 · **Статус:** 🔴 Открыто — требуется решение владельца

**Контекст.** Шесть источников утверждают взаимоисключающие вещи (детали — в
`AUDIT_2026-07-25.md`, п. 1.3):

| Источник | Утверждает |
|---|---|
| `public/legal/privacy.html` §3 | используется Google Analytics с cookies |
| `public/legal/terms.html` §7 | персональные данные не собираются вообще |
| `README.md` | «No tracking: No analytics or third-party services» |
| `index.html` (JSON-LD `featureList`) | «No tracking» |
| `src/app/index.html` (meta description) | «no tracking» |
| `ANALYTICS_GUIDE.md` | Google Analytics использовать запрещено |

При этом GA физически не подключён: вызов `gtag` в `src/app/app.js:414` обёрнут в проверку,
которая всегда ложна, а скрипта загрузки нет ни на одной странице. То есть сейчас
задекларирован сбор данных, которого не происходит.

**Варианты:**

- **А. Остаться на «no tracking», внедрить Cloudflare Web Analytics.** Без cookies, не
  требует consent-баннера, не противоречит позиционированию. Откатить §3 Privacy Policy,
  удалить мёртвый `gtag`-блок. Это ровно то, что рекомендует собственный `ANALYTICS_GUIDE.md`.
  *Минус:* меньше данных, чем в GA.
- **Б. Подключить Google Analytics по-настоящему.** Тогда обязательны: cookie-consent баннер
  для EU (иначе нарушение ePrivacy и GDPR), правка Terms §7, правка README и JSON-LD, ревизия
  §6 про детей. *Минус:* теряется главное конкурентное преимущество продукта.
- **В. Никакой аналитики.** Полностью согласуется с текущим позиционированием, но решения по
  продукту принимать не на чем.

**Рекомендация:** вариант А.

**Пока решение не принято** запрещено добавлять любые сторонние скрипты аналитики и трекинга,
а также менять формулировки о приватности в отдельных файлах — расхождение только вырастет.

## 0004. Лицензия и Terms of Service

**Дата:** 2026-07-25 · **Статус:** 🔴 Открыто — требуется решение владельца

**Контекст.** Три несовместимых утверждения:

- `README.md` заявляет MIT License и приглашает форкать и присылать PR;
- файла `LICENSE` в репозитории **нет** — без него действует «все права защищены», и ссылка
  на MIT юридически не работает;
- `public/legal/terms.html` §8 запрещает копировать, изменять, распространять код и
  использовать приложение в коммерческих целях без разрешения.

MIT разрешает ровно то, что Terms §8 запрещает. Сейчас человек, форкнувший проект по
приглашению README, формально нарушает Terms.

**Варианты:**

- **А. Открытый проект.** Добавить `LICENSE` (MIT), переписать Terms §8 так, чтобы он
  относился к бренду, домену и контенту статей, а не к коду.
- **Б. Закрытый проект.** Убрать из README упоминания MIT, open source и раздел Contributing;
  Terms §8 оставить.
- **В. Разделить.** Код под MIT, контент research-статей и бренд — под ограничениями. Требует
  аккуратной формулировки в обоих документах.

**Влияние на бизнес.** Вариант Б закрывает путь к корпоративным лицензиям без индивидуальных
переговоров, вариант А — открывает форки продукта. Это решение о стратегии, не о коде.

**Пока решение не принято** не ссылаться на лицензию в новых файлах и не добавлять
copyright-заголовки в исходники.

## 0005. Правила проекта версионируются в git

**Дата:** 2026-07-25 · **Статус:** Принято

**Контекст.** До этой даты правила разработки существовали в виде локального `CLAUDE.md`,
намеренно внесённого в `.gitignore`. Файл не версионировался, не ревьюился и не переезжал
между машинами и сессиями, поэтому неизбежно устарел и разошёлся с кодом. За всю историю
репозитория из документации коммитились только `README.md`, `DEPLOYMENT_GUIDE.md` и
`ANALYTICS_GUIDE.md`.

**Решение.** Вся документация по правилам лежит в git: `CONTRIBUTING.md` как точка входа и
`docs/` для деталей. `CLAUDE.md` убран из `.gitignore` и превращён в короткий файл-указатель
на `CONTRIBUTING.md`, чтобы AI-сессии и человек читали один и тот же набор правил.

**Причина.** Неверсионированное правило нельзя ни исполнить, ни обновить, ни оспорить. Правило
вне git — это не правило, а чья-то память.

**Что стало бы поводом передумать.** Ничего. В `.gitignore` может попадать только личная
конфигурация (`.vscode/`, `*.local`), но не правила.
