# Стиль кода

Правила написания JS, CSS и HTML в этом проекте. Почти каждый запрет ниже выведен из
конкретной ошибки, которая уже есть в коде — ссылки на места приведены.

**Последний пересмотр:** 2026-07-25 · **Следующий:** 2027-01-25

---

## Форматирование

Проверяется машиной, не глазами. Настройки — в `.editorconfig`, читаются большинством
редакторов автоматически.

| | |
|---|---|
| Отступ | 2 пробела, табы запрещены |
| Переносы строк | LF |
| Кодировка | UTF-8 |
| Пробелы в конце строк | Срезаются (кроме `.md`) |
| Перевод строки в конце файла | Обязателен |

НЕ НУЖНО: переформатировать файл заодно с содержательной правкой. Дифф становится
нечитаемым, а ревью — бессмысленным. Переформатирование — отдельный коммит типа `style`.

## JavaScript

### Базовые соглашения

Соответствуют тому, как написана большая часть кода — это не новые требования, а фиксация
сложившегося:

- НУЖНО: одинарные кавычки для строк. Шаблонные литералы — когда есть подстановка или
  многострочность.
- НУЖНО: точки с запятой. (`vite.config.js` — единственный файл без них, это исключение,
  а не образец.)
- НУЖНО: `const` по умолчанию, `let` — если значение действительно переприсваивается.
  `var` запрещён.
- НУЖНО: `camelCase` для переменных и функций, `PascalCase` для классов,
  `SCREAMING_SNAKE_CASE` для констант уровня модуля.
- НУЖНО: `'use strict'` в файлах, которые подключаются как обычные скрипты, а не модули
  (всё в `public/scripts/` и `public/tools/`).
- СТОИТ: строгое сравнение `===`. Исключение — проверка на `null`/`undefined` через `== null`.

### Обращение к DOM

**Проверять результат `querySelector`.** НУЖНО.

```js
// Плохо — падает с TypeError, если элемента нет
document.querySelector(`[data-duration="${duration}"]`).classList.add('active');

// Хорошо
const btn = document.querySelector(`[data-duration="${duration}"]`);
if (btn) {
  btn.classList.add('active');
}
```

Это не теория: `src/app/app.js:245` содержит первый вариант. Если в `localStorage` окажется
кастомная длительность (например, `7`), кнопки с таким `data-duration` не существует и
приложение не запустится вообще.

**Никогда не подставлять данные в `innerHTML`.** НУЖНО.

```js
// Плохо — pair.thought приходит из пользовательского ввода
dropdown.innerHTML = `<div data-id="${item.id}">${pair.thought}</div>`;

// Хорошо — текст через textContent, он не парсится как HTML
const div = document.createElement('div');
div.dataset.id = item.id;
div.textContent = pair.thought;
```

`innerHTML` МОЖНО использовать только для статической строки без единой подстановки.

В проекте сейчас два разных стандарта: `src/app/app.js:653` экранирует корректно через
`escapeHtml()`, а `public/tools/end-prompt.js:215` подставляет пользовательский текст напрямую.
Практическая опасность второго ограничена self-XSS, но паттерн станет настоящей уязвимостью,
как только появится импорт или шеринг данных.

**SVG создаётся только через `createElementNS`.** НУЖНО.

```js
// Плохо — создаёт HTMLUnknownElement, графика не рендерится
const icon = document.createElement('svg');

// Хорошо
const NS = 'http://www.w3.org/2000/svg';
const icon = document.createElementNS(NS, 'svg');
const path = document.createElementNS(NS, 'path');
```

`document.createElement()` в HTML-документе всегда создаёт элемент в HTML-namespace. Тег `svg`
в HTML-namespace — не графика, атрибуты вроде `viewBox` не действуют, дочерние элементы,
вставленные через `innerHTML`, тоже оказываются не в том namespace.

Из-за этой ошибки в `public/scripts/theme-toggle.js:105` кнопка переключения темы не
показывает иконку **ни на одной из 20 страниц**. Ошибка не даёт исключения — просто пустой
круг, поэтому она и прожила до аудита.

### Время и даты

**Отсчёт — от абсолютной метки времени, не декрементом.** НУЖНО.

```js
// Плохо — накапливает дрейф и замирает в фоне
this.timeLeft = duration * 60;
setInterval(() => { this.timeLeft--; }, 1000);

// Хорошо — источник правды один, интервал только перерисовывает
this.endsAt = Date.now() + duration * 60 * 1000;
setInterval(() => {
  const left = Math.max(0, Math.round((this.endsAt - Date.now()) / 1000));
  this.render(left);
}, 250);
```

Интервал `setInterval` никогда не равен ровно 1000 мс, а в фоновых вкладках браузер его
тормозит или замораживает. Для продукта, чьё название — обещание про 10 минут, точность
отсчёта входит в само обещание. Сейчас первый вариант используется в четырёх местах:
`src/app/app.js:354`, `public/tools/10-minute-timer.html`, `public/tools/breathing-pacer.html`,
`app/app.js`.

**Календарные даты — локальные, не UTC.** НУЖНО.

```js
// Плохо — возвращает дату по UTC, а не по часовому поясу пользователя
const today = new Date().toISOString().split('T')[0];

// Хорошо
function localDate(d = new Date()) {
  return [
    d.getFullYear(),
    String(d.getMonth() + 1).padStart(2, '0'),
    String(d.getDate()).padStart(2, '0'),
  ].join('-');
}
```

`toISOString()` переводит время в UTC. Для пользователя в UTC+3 после 21:00 «сегодня» по UTC —
уже завтра, поэтому вечерняя и утренняя сессии попадают в одну дату и серия дней считается
неверно. Затрагивает `src/app/app.js:535` и `567`.

### Асинхронность и ошибки

**Промисы обрабатываются, а не глотаются `try/catch`.** НУЖНО.

```js
// Плохо — try/catch не перехватывает отклонение промиса
try {
  const audio = new Audio('/sounds/timer-complete.mp3');
  audio.play();
} catch (e) {}

// Хорошо
new Audio('/sounds/timer-complete.mp3').play().catch(() => {
  // Автоплей заблокирован — звук не критичен
});
```

Пример из `src/app/app.js:427`: воспроизведение происходит через 10 минут после жеста
пользователя, поэтому браузер его вполне может заблокировать — и это даёт необработанное
отклонение промиса.

**Пустой `catch` — только с комментарием, почему ошибку можно игнорировать.** НУЖНО. Без
комментария такой блок нельзя отличить от забытой обработки.

**Каждое обращение к `localStorage` защищено.** НУЖНО — см. `ARCHITECTURE.md`, раздел
«Состояние». Эталон — `public/scripts/theme-toggle.js:16-33`.

### Логирование

- НЕ НУЖНО: `console.log` в коде, попадающем в production. Отладочные логи удаляются до
  коммита.
- МОЖНО: `console.warn` и `console.error` для ситуаций, о которых полезно знать из
  консоли пользователя.
- НЕ НУЖНО: логировать в горячих путях. В `public/app/sw.js` логируется **каждый**
  перехваченный запрос (строки 68 и 73) — это уже не шум, а накладные расходы.

Сейчас в проде остаётся 15 вызовов `console.log`, включая `src/app/app.js:421` с комментарием
`// Для отладки`. Коммит `6d0de71` заявлял их удаление.

### Комментарии

- НУЖНО: комментарий объясняет **почему**, а не **что**. `// увеличиваем счётчик` не нужен
  никому, `// сбрасываем, потому что пользователь переключился в другое приложение` — нужен.
- СТОИТ: JSDoc для экспортируемых функций. Образец — `public/scripts/theme-toggle.js`,
  единственный файл в проекте с JSDoc.
- НУЖНО: комментарии на английском (см. `CONTRIBUTING.md` → «Язык»).
- НЕ НУЖНО: закомментированный код. Для истории есть git. Пустой обработчик из одних
  комментариев (`src/app/app.js:770-775`) — тот же случай.
- НУЖНО: помечать сознательно отложенное как `// TODO(<причина или ссылка>):`. Немаркированное
  недоделанное неотличимо от бага.

## CSS

### Переменные

НУЖНО: цвета и отступы — через кастомные свойства из `:root`. Захардкоженный цвет ломает
светлую тему.

```css
/* Плохо */
color: #ffffff;

/* Хорошо */
color: var(--text-primary);
```

Оба набора переменных (`:root` и `[data-theme="light"]`) объявлены в `public/styles/common.css`
и `src/app/style.css`. НУЖНО: добавляете переменную — добавьте её в **оба** блока темы, иначе
в одной из тем она окажется неопределённой.

Живой пример нарушения: `src/app/app.js:314-326` создаёт элемент с `color: #ffffff` в inline-
стилях — в светлой теме этот текст становится белым на белом.

### `!important` запрещён

НУЖНО: вместо повышения приоритета — исправить селектор.

В проекте 44 объявления `!important` (19 в `common.css`, 25 в `src/app/style.css`). Это не
стилевая придирка: каждое из них делает следующую правку дороже, потому что перебить его можно
только ещё одним `!important`. История коммитов это подтверждает — есть коммит с сообщением
«use more specific CSS selector with hero-section context and !important».

Исключение: перебивание стилей, которые нельзя контролировать иначе (inline-стили из
сторонней разметки). Требует комментария с причиной на той же строке.

### Прочее

- НУЖНО: `kebab-case` в именах классов.
- СТОИТ: имя класса отражает роль, а не вид. `.btn-primary` доживёт до редизайна,
  `.btn-green` — нет.
- СТОИТ: глубина селекторов не больше трёх уровней.
- НУЖНО: mobile-first — базовые правила без медиазапроса, расширения через `min-width`.
- НУЖНО: стили статических страниц — в `public/styles/common.css`, стили приложения —
  в `src/app/style.css`. Не смешивать: у файлов разная судьба при сборке (первый не
  минифицируется и не хешируется).

## HTML

### Обязательное на каждой странице

НУЖНО, проверяется вручную при добавлении страницы:

1. `<html lang="en">`
2. `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
3. Уникальный `<title>`
4. Уникальный `<meta name="description">`
5. `<link rel="canonical">` с абсолютным URL **без** `.html`
6. Ровно один `<h1>`
7. Открывающие теги Open Graph и Twitter, если страницу будут шерить
8. Запись в `public/sitemap.xml`
9. Стандартный футер с семью ссылками

Текущее покрытие: 20 из 21 страницы соблюдают пункты 1–5. Пункт 6 нарушен на
`src/app/index.html` — это единственная страница без `<h1>`.

### Ссылки

- НУЖНО: внутренние ссылки без `.html` — Cloudflare Pages всё равно сделает 308-редирект,
  а лишний переход портит и скорость, и индексацию.
- НУЖНО: `rel="noopener noreferrer"` при `target="_blank"`.
- НУЖНО: проверять, что цель ссылки существует. В `public/research/why-10-minutes.html:107-108`
  две ссылки ведут на несуществующие страницы.

### Доступность

- НУЖНО: у каждого поля ввода — `<label>` или `aria-label`. Placeholder подписью не является:
  скринридер его не озвучивает как имя поля. Нарушено для `#custom-minutes`
  в `src/app/index.html`.
- НУЖНО: у иконочных кнопок без текста — `aria-label`.
- НУЖНО: иерархия заголовков без пропусков — `h1` → `h2` → `h3`.
- НУЖНО: у `<img>` атрибут `alt` (сейчас соблюдается везде).

### Скрипты

- НУЖНО: `defer` или `type="module"` для скриптов в `<head>`. Синхронный скрипт блокирует
  разбор документа.
- МОЖНО: маленький синхронный inline-скрипт в `<head>` — но **только** чтобы применить тему
  до первой отрисовки. Это единственное оправданное исключение: без него пользователь светлой
  темы видит вспышку тёмной, что происходит сейчас на всех 20 страницах.
- СТОИТ: выносить логику в отдельные `.js`-файлы. Inline-скрипты в
  `public/tools/10-minute-timer.html` и `breathing-pacer.html` не дадут включить строгую CSP.
